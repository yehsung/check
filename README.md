# aing-check

작은 Mac 팀을 위한 메뉴바 근무 타이머입니다. 상단바에서 근무 시작/종료를 누르면 팀 전체에 실시간으로 공유되고, 근무하는 동안 화면 구석에서 3D 캐릭터 "아잉"이 함께 일합니다.

출퇴근 카드나 근태 시스템을 들이기엔 작은 팀, 서로 지금 누가 일하고 있는지만 알면 되는 몇 명짜리 팀을 위해 만들었습니다. 메뉴바에 띄워 둔 채 버튼 하나로 쓰고, 근무 기록 위에 주간 목표와 지난주 회고, AI 토큰 사용량을 얹었습니다. 의존성 없는 SwiftUI 네이티브 앱(macOS 14 이상)이고, 팀 데이터는 Supabase에 저장됩니다.

## 기능

### 근무 기록

- **원클릭 근무 시작/종료** — 메뉴바에 오늘 누적 시간이 흐릅니다. 쉬었다 재개해도 0부터가 아니라 오늘 총합에서 이어집니다.
- **주간 목표 진행 바** — 내 근무 상자에서 이번 주 누적과 목표 대비 달성률을 함께 봅니다. 목표는 팀 총합이 아니라 "각자 이번 주 이만큼은 하자"는 1인당 약속이고, 팀원 누구나 연필 버튼으로 조정할 수 있습니다.
- **자동 근무 시작** — 쉬는 중에 컴퓨터를 계속 쓰고 있으면 아잉이 "일하는 것 같아서 근무 시작했어요!" 하고 알리며 근무를 대신 시작해 줍니다. 켜고 끄는 설정은 없고, 원하지 않으면 근무 종료를 누르면 됩니다.
- **깜빡 잊은 퇴근 정리** — 맥이 오래 잠들거나 앱이 한참 자리를 비운 채 남아 있던 근무는 마지막으로 확인된 시각으로 정리됩니다. 자리 비움으로 종료된 근무는 그 직후 잠깐 동안 팝오버에 뜨는 [되돌리기]로 다시 살릴 수 있습니다.
- **12시간 확인** — 12시간 넘게 근무 중이면 "아직 근무 중이신가요?" 하고 한 번 물어봅니다. [네, 근무 중이에요]로 이어 가거나 [지금 종료]로 그 자리에서 바로 퇴근할 수 있습니다.
- **끊겨도 괜찮게** — 인터넷이 잠깐 끊긴 동안 누른 시작/종료도 사라지지 않고, 연결이 돌아오면 누른 순서대로 반영됩니다.

### 팀과 함께

- **팀원 현황** — 누가 지금 근무중인지, 각자의 현재 근무 시간과 이번 주 누적, 그리고 각자의 주간 목표 진행 바를 한 화면에서 봅니다. 프로필 아바타는 각자 직접 고를 수 있습니다.
- **초대코드로 팀 참여** — 공개 팀 목록은 없습니다. 코드가 곧 열쇠입니다. 가입하면서 새 팀을 만들면 참여코드가 자동 발급되고, 팀원 누구나 열쇠 버튼으로 코드를 꺼내 새 동료를 초대할 수 있습니다.
- **팀별 이번 주** — 팀 규모가 달라도 공정하게, 1인당 평균 기준으로 팀들을 비교합니다.
- **콕 찌르기** — 앱을 쓰는 다른 사용자를 콕 찔러 알림을 보낼 수 있습니다. 찔린 사람의 캐릭터가 화들짝 놀라며 누가 찔렀는지 말풍선으로 알려 주고, 캐릭터를 숨겨 둔 사람에게도 잠깐 나타났다 사라집니다. 서로 근무 중일 때만 찌를 수 있고, 같은 사람을 연달아 찌를 수는 없습니다.

### 내 기록 돌아보기

- **근무 리듬 히트맵** — 지난주 한 주 동안 어떤 요일 어떤 시간대에 일했는지 격자로 볼 수 있고, 가장 활발했던 시간을 짚어 줍니다. 바로 아래 지난주 회고와 같은 주를 보여 주며, 칸이 진할수록 그 한 시간을 오래 채워 일했다는 뜻입니다.
- **지난주 회고** — 지난주 총 근무시간, 목표 대비 달성 정도, 전주 대비 증감, 근무 세션 수, 가장 많이 일한 요일을 카드 한 장으로 정리합니다.
- **주가 바뀌면 한 번 안내** — 새 주가 시작되고 팝오버를 처음 열면 지난주 기록이 준비됐다는 안내가 한 번 뜹니다. [보기]를 누르면 곧바로 회고로 갑니다.
- 이 화면은 내 근무 기록만으로 만들어지며, 다른 팀원에게는 보이지 않습니다.

### AI 토큰 사용량

- **이번 달 소모량** — 이 맥의 Claude Code·Codex 로컬 기록으로 이번 달 토큰 소모량을 집계해 팝오버에 보여 줍니다. 매달 1일에 새로 시작합니다.
- **전체 순위판** — 앱을 쓰는 사용자들의 이번 달 소모량을 나란히 놓고 비교할 수 있습니다. 각자 오늘 얼마나 늘었는지도 함께 보이고, ‹ › 로 지난달과 그 이전 달 순위도 넘겨 볼 수 있습니다.
- **맥을 여러 대 써도** — 맥이 두 대 이상이면 각 맥에서 쓴 양이 합산되어 하나로 보입니다.
- **공개할지는 내가** — 순위판의 눈 버튼으로 내 사용량을 비공개로 바꿀 수 있습니다. 비공개로 두면 다른 사람의 순위판에서는 빠지고 내 순위판에서만 보입니다.

### 캐릭터 아잉

- **함께 일하는 캐릭터** — 근무하는 동안 화면 구석에 3D 캐릭터가 떠 있습니다. 출근하면 폴짝 뛰어오르고, 퇴근할 땐 꾸벅 인사하고 사라집니다.
- **리액션** — 클릭하면 "아얏!" 하고 반응합니다. 오늘 1시간·4시간을 넘기거나 주간 목표를 채우면 색종이가 터지고, 팀원이 근무를 시작하면 그 이름을 부르며 인사합니다. 한동안 조용하면 눈을 감고 꾸벅 졸다가 클릭하면 화들짝 깨어납니다.
- **작업을 방해하지 않게** — 캐릭터 몸 위 클릭만 캐릭터가 받고 주변 여백은 뒤 창으로 통과됩니다. 드래그로 위치를 옮길 수 있고(이동 방향을 바라보며 따라옵니다) 그 자리를 기억합니다. 사람 아이콘 버튼으로 아예 숨길 수도 있습니다.

### 안심하고 쓰기

- **업데이트 알림** — 새 버전이 나오면 팝오버 맨 위에 안내가 뜨고, 이번 버전에서 바뀐 내용도 몇 줄로 함께 보여 줍니다. [지금 업데이트] 한 번으로 설치까지 끝나고, 여의치 않으면 [명령 복사]로 직접 실행할 수 있습니다. 캐릭터도 말풍선으로 한 번 알려 줍니다.
- **보지 않는 것** — 스크린샷, 키보드 입력, 마우스 움직임, 앱·웹사이트 사용 기록은 수집하지 않습니다. Accessibility·화면 기록·카메라·마이크·위치 권한도 요청하지 않습니다.
- **가볍게** — 메뉴바에 계속 띄워 두어도 부담이 없도록 만들었습니다. 3D 렌더는 캐릭터를 표시할 때만 켜집니다.

클라이언트는 Swift Package 하나이고, 화면에 필요한 상태는 `@Observable` 스토어(`WorkTimerStore`) 한 곳에 모입니다. 팝오버와 캐릭터 오버레이는 같은 스토어를 읽는 두 개의 표시 표면일 뿐이라, 근무 상태가 두 벌로 갈라지지 않습니다. 서버 접근은 REST/RPC 한 계층(`SupabaseWorkService`)만 통과하고, 오프라인에서 누른 시작/종료는 그 계층 앞의 큐에 쌓였다가 순서대로 재전송됩니다.

내 소유 행(근무 세션·상태·프로필·토큰 원장)은 PostgREST로 직접 읽고 쓰되 RLS가 경계를 지키고, 남의 데이터가 섞이거나 규칙을 강제해야 하는 일 — 초대코드로 팀 참여, 팀·토큰 순위 집계, 찌르기 조건과 쿨타임, 방치 세션 마감 — 은 전부 `security definer` RPC를 거칩니다. 팀·소속·찌르기 테이블에는 아예 쓰기 정책이 없어 RPC 경유가 구조적으로 강제됩니다. 앱을 켜 두지 않아도 되는 정리 작업(방치 세션 마감, 오래된 찔림 삭제)은 pg_cron이 주기로 돌립니다.

AI 토큰 사용량만은 서버가 알 수 없는 값이라, 각자의 맥에서 로컬 세션 로그를 증분 스캔해 숫자만 집계한 뒤 월별 원장에 올립니다. 대화 내용이나 파일 경로는 읽지도 보관하지도 않습니다.

| 경로 | 역할 |
| --- | --- |
| `Sources/check/` | 앱 전부 — 팝오버 UI, 캐릭터 오버레이, 상태 스토어, Supabase 계층, 토큰 스캐너, 3D·이미지 리소스 |
| `Tests/checkTests/` | 단위 테스트, 팝오버 렌더 스냅샷, 옵트인 라이브 e2e |
| `supabase/migrations/` | 테이블·RLS 정책·RPC·cron 잡 스키마 |
| `scripts/` | 로컬 빌드, 서명·공증 패키징, brew 릴리스 |
| `packaging/` | 앱 아이콘과 Homebrew cask 정의 |
| `docs/` | 설치·배포·프라이버시 문서와 이미지 |

데이터는 근무 기록·팀·토큰 집계만 Supabase에 저장되고, 로그인 세션과 화면 설정(캐릭터 위치·표시 여부 등), 토큰 스캔 캐시는 이 맥에만 남습니다.

## 설치

```sh
brew install yehsung/check/aing-check
```

앱은 Apple 공증(notarized)이 되어 있어 경고 없이 바로 열립니다. 이후 업데이트는 `brew upgrade --cask aing-check`. (brew 가 없다면 [GitHub Releases](https://github.com/yehsung/check/releases)에서 `aing-check.zip`을 받아 풀고 앱을 응용 프로그램 폴더로 옮겨도 됩니다.)

처음이면 별명·이메일·비밀번호와 팀 코드로 가입하고(팀이 없으면 "새 팀 만들기"), 이후엔 근무 시작 버튼만 누르면 됩니다. 자세한 안내: [docs/team-install.md](docs/team-install.md)

## 개발

Swift Package(SwiftUI `MenuBarExtra`) + Supabase(Auth/REST, RLS). 서버 스키마는 `supabase/migrations/`.

```sh
export CHECK_SUPABASE_ANON_KEY="<Supabase anon key>"   # 또는 .env.local (git 제외)
swift test                  # 전체 테스트
./scripts/build-local.sh    # → dist/aing-check.app
```

테스트는 세 종류입니다. 순수 로직 단위 테스트(집계·포매팅·동기화 상태 전이)와, 팝오버를 `ImageRenderer`로 그려 레이아웃과 창 높이 상한을 지키는지 확인하는 렌더 스냅샷 테스트가 기본으로 돌고, 실제 Supabase 프로젝트를 상대로 하는 라이브 e2e 테스트는 `CHECK_E2E=1`과 키 파일을 줄 때만 켜집니다.

릴리스는 `CHANGELOG.md`에 이번 버전 내용을 먼저 적고 — 그 내용이 GitHub 릴리스 노트가 되고 앱 안 업데이트 배너의 패치노트로도 쓰입니다 — 빌드·서명·공증을 거쳐 GitHub Release와 Homebrew tap을 갱신하는 순서입니다. 명령과 운영 주의사항은 [docs/release.md](docs/release.md)에 있습니다.
