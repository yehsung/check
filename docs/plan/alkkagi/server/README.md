# PR에 포함하는 서버 변경

이 폴더는 검토할 SQL 원본과 로컬 통합 테스트를 함께 관리한다. 기존
`docs/plan/tetris-broadcast/server/`와 같은 서버 초안 보관 방식이다.
운영 마이그레이션 원본인 `supabase/migrations/`는 이 공개 저장소에서 Git 대상이 아니다.
리뷰와 통합이 끝난 SQL은 저장소 관리자가 비공개 마이그레이션 체인에 등록하고 앱보다 먼저 배포한다.
여기 파일을 추가하거나 PR을 여는 동작 자체가 운영 DB에 적용하지는 않는다.

| 적용 순서 | 파일 | 역할 |
| --- | --- | --- |
| 1 | `20261108160000_alkkagi_physics.sql` | 고정 간격 서버 물리 계산. 앱이 승패나 점수를 제출하지 않는다. |
| 2 | `20261108161000_alkkagi_matches.sql` | 초대, 동시 비공개 배치, 발사, 차례와 시계, 채팅 및 권한 검사. |
| 3 | `20261108162000_alkkagi_progress.sql` | 최초 경기 종료의 영구 누적 집계와 KST 일일 집계. |

세 파일은 순서대로 하나의 마이그레이션 트랜잭션에서 적용한다. 운영 DB의 기존 객체를 추정해
덮어쓰지 않으며 의존성, 이름 충돌과 소유권 검사가 실패하면 중단한다.
`harness/bootstrap.sql`은 테스트 역할과 가짜 사용자를 만드는 파일이므로 운영에 적용하지 않는다.

## 기존 오목과 같은 연결

본앱은 오목과 동일한 Supabase 프로젝트, `duelRPC`, 로그인 세션과 갱신 경로를 사용한다.
기존 private `poke:<사용자 UUID>` 채널의 `alkkagi` 이벤트를 받아 권한을 검사하는 RPC로 다시 조회한다.
별도 게임 서버나 새로운 로그인 토큰 저장소를 추가하지 않는다.

두 사람이 같은 30초 동안 자기 영역에 돌 5개를 배치한다. 준비하면 자기 배치를 잠그고,
둘 다 준비하거나 마감이 지나면 모든 돌을 공개한 뒤 흑돌이 시작한다. 마감에는 미배치 돌만 자동 배치한다.
배치 중 응답은 본인 돌 5개만 포함한다. 일반 조회, 로비, 채팅, 중복 요청과 오류 응답에도 같은 투영을 적용한다.
배치 중 기권한 판에서도 상대 좌표를 공개하지 않는다.
`placement_revision`은 회원별로 관리하므로 상대가 움직여도 내 입력이 오래된 요청으로 거절되지 않는다.

경기 종료는 서버가 확정한다. `onMatchFinished`는 같은 판의 종료를 처음 관측했을 때만 실행하고,
오목과 같은 `refreshAchievementsAfterGameResult`로 기존 미션 상태를 다시 받는다.
보상 수령은 공통 `achievement_claim`과 `daily_mission_claim`을 그대로 사용한다.

## 비공개 서버 원본과 함께 통합할 부분

다음 원본이 공개 저장소에 없으므로 이 PR에서 정의를 추측하거나 기존 함수를 자동 치환하지 않는다.
실제 체인을 가진 관리자가 아래 항목을 함께 반영해야 운영 계정에서 완성된다.

1. **공용 대전 중 판정:** `alk_busy(uuid)`를 기존 `game__busy_users()`에 연결한다.
   알까기의 초대, 수락과 상대의 busy 표시도 기존 다른 게임의 진행 상태를 확인하도록 연결한다.
   현재 초안 자체는 알까기끼리의 중복 대전만 막는다. 양쪽 방향의 연동을 함께 검증한다.
2. **누적 도전과제:** 기존 오목의 계열, 목표와 보상 정의를 확인해 알까기 계열로 등록한다.
   키는 `alkkagi` 접두어를 사용하고 오목의 진행도로 기록하지 않는다.
3. **일일 미션:** 키 `daily_alkkagi`, 게임 `alkkagi`를 기존 메타데이터와 조회 및 수령 판정에 추가한다.
   기존 오목의 보상액과 보상 대상 경기 조건을 재사용한다. `alk_progress(uuid)`는 서버 소유자만 읽을 수 있는
   원본 경기 집계다. 이 집계가 보상 대상에 해당하는지는 기존 오목의 실제 정책과 대조해야 한다.
4. **지급과 중복 방지:** 기존 잔액 및 지급 원장에 알까기 미션을 연결한다. 조회 콜백이나 앱의 로컬 계산으로
   보상을 더하지 않는다. 같은 키를 다시 수령해도 지급이 한 번인지 기존 수령 API로 확인한다.
5. **보관과 계정 삭제:** 종료된 초대 1일, 끝난 판 30일 보관안을 기존 운영 정리 작업에 통합한다.
   진행 중인 판과 action ID를 시간만으로 지우지 않는다. 경기 행 정리가 누적 집계를 지우지 않는지,
   실제 계정 삭제 경로에서는 해당 사용자의 집계와 게임 외래 키가 함께 정리되는지 확인한다.

도전과제의 실제 메타데이터와 보상 지급 통합은 위 작업 전까지 적용되지 않는다.
새 집계 SQL은 기존 미션 함수나 잔액을 변경하지 않는다.

## 검증

실행 방법은 [상위 문서](../README.md)에 있다. 독립 Swift 패키지와 실제 PostgreSQL/PostgREST에
서로 다른 테스트 JWT를 보낸다. 실제 프로젝트의 JWT나 관리 키는 테스트에 필요하지 않다.

- 동시 배치, 회원별 수정 번호, 준비 잠금과 공통 마감.
- 상대 돌이 조회, 오류, 채팅과 재시도 응답에서 공개되지 않는지.
- 양쪽이 경계에 돌을 놓아도 숨겨진 상대 위치 때문에 배치가 거절되지 않는지.
- 서버 물리 계산, 중복 발사, 차례와 시계, 채팅 순번 및 권한.
- 최초 종료의 누적 및 일일 집계, 재조회와 재시도, 경기 행 정리 뒤 집계 유지.

운영 반영 후에는 두 실제 계정으로 private Realtime 알림, 재접속, 기존 게임과의 중복 대전 차단,
알까기 도전과제와 일일 미션의 진행 및 수령을 검증한다.

## check 통합(2026-11-09, 메인테이너)

이 폴더의 SQL 은 기여 원본으로 남긴다. 운영에 올리는 판은 비공개 마이그레이션 폴더의 한 장으로, 이 두 장(물리 · 대전)을 그대로 싣고
아래만 고쳤다. 진행 집계(`20261108162000_alkkagi_progress.sql`)는 미션을 아직 잇지 않아 싣지 않았다.

- 대국 중 판정을 다른 게임과 한 곳(공용 대국 중 집합)으로 합치고, 수락 잠금을 다른 1:1 과 같은 키로 잡는다.
- 차례 시간을 세 번 연달아 넘긴 쪽이 진다(`finish_reason: timeout`). 아무도 보지 않는 판은 매분 서버가 앞으로 민다. 끝난 신청 · 판은 보관 기간 뒤 지운다.
- 상태 조회는 판 행을 기다리지 않고, 쓰는 길에는 잠금 시간 상한을 둔다.
- 맥 build 문(끌 스위치)을 둔다 — 출시 때 연다.
- 운영 반영 방식(트랜잭션 밖 파일 적용)에 맞추고 다시 적용해도 같게 했다. 배치는 숨긴 배치라 찌르기 알림을 보내지 않고, 다시 놓기에 상한을 둔다.

앱 쪽: 판 중 걸음은 판 상태만 읽는다(로비 · 사람 목록을 걸음마다 부르지 않는다). 사람 목록은 30초에 한 번.
