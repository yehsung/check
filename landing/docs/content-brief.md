## 1. 제품 정의 한 줄 (3안)

1. **작은 Mac 팀을 위한 메뉴바 근무 타이머.** README 첫 줄 그대로다. 가장 정확하고 범주가 바로 읽힌다. 메타 설명과 OG 에 쓴다.
2. **일하는 시간을 스스로 재고, 팀이 지금 어디쯤인지 한눈에 보는 앱.** `docs/index.md` 첫 문단이다. 맥과 아이폰을 함께 말할 때 쓴다(지원 페이지와 같은 문장).
3. **팀 출퇴근 관리를 위한 근무 타이머.** v4 영상 CTA 부제로 사용자가 확정한 문장(✓v4)이다. 히어로 리드나 푸터 한 줄에 맞다.

권장: 히어로 리드는 3안과 README 첫 문단을 섞은 문장(§4), `<title>`·OG 는 "아잉체크 — 작은 Mac 팀을 위한 메뉴바 근무 타이머".

## 2. 포지셔닝

- **누구를 위한가**: 출퇴근 카드나 근태 시스템을 들이기엔 작고, 서로 지금 누가 일하는지만 알면 되는 몇 명짜리 팀(README 첫 문단). 메뉴바에 띄워 두고 버튼 하나로 쓰는 Mac 사용자. 앞에 내세울 두 번째 축은 **AI 코딩 도구를 쓰는 개발자**다. 토큰 사용량 순위판과 Claude Code·Codex·Antigravity 리밋을 메뉴바에서 바로 본다.
- **어떤 감정인가**: 감시가 아니라 "같이 켜 두는" 느낌이다. 서로 보이고, 콕 찌르고, 일한 만큼 캐릭터를 모은다. 사용자가 v3 영상 기획에서 쓴 내부 콘셉트는 "개발자들의 열품타"다(메모리 promo-v3-direction). 타사 이름이라 **공개 문구에는 쓰지 않고** 방향을 잡는 데만 쓴다.
- **왜 지금(해석이며 수치 주장이 아님)**: 같은 팀이라도 자리와 시간이 흩어져 일하고, AI 도구 사용량과 리밋을 들여다보는 일이 매일 반복된다. 이 앱은 그 두 가지를 메뉴바 한 칸에 모은다. "몇 %의 팀이" 같은 통계 문장은 근거가 없으니 쓰지 않는다.
- **차별점(전부 사실)**: ① 앱을 켜 두기만 해도 자동 시작·자동 마감이 된다 ② 근무하는 동안 실제 3D 캐릭터가 화면 구석에 있다 ③ 보지 않는 것을 문서로 공개해 두었다 ④ 맥과 아이폰이 한 계정으로 이어지고 위젯도 있다 ⑤ 무료이고 외부 SDK 가 없다.

## 7. FAQ (10문항) — 제목 후보 「궁금한 것들.」(Aingo 와 같은 문법) / 「자주 묻는 것.」

1. **요금이 있나요?**
   무료예요. 앱 안에서 현금 결제를 받지 않고, 루비는 일하거나 게임해서 모으는 앱 안 재화라 현금으로 사거나 바꿀 수 없어요. — `docs/terms.md` §1, App Store 실측 '무료'
2. **어떤 기기에서 쓰나요?**
   맥은 macOS 14 이상이면 Apple Silicon·Intel 모두 돼요. 아이폰은 iOS 18 이상이에요. 근무 시작·종료는 맥에서 하고, 아이폰에서는 현황·메시지·할 일·게임을 써요. — `scripts/build-local.sh`, `CheckAppLinks.swift:21`, `docs/privacy.md` §폰이 하지 않는 것
3. **팀 코드는 어디서 받나요?**
   이미 쓰는 팀원에게 받아요. 팀원 누구나 팀 카드의 열쇠 버튼에서 코드를 보고 복사할 수 있어요. 팀이 없으면 가입할 때 '새 팀 만들기'를 누르면 코드가 바로 생겨요. 공개된 팀 목록은 없어요. — README '초대코드로 팀 참여', `docs/team-install.md` §2
4. **화면이나 키 입력을 보나요?**
   아니요. 스크린샷·키보드 입력·마우스 움직임·앱과 웹 사용 기록을 모으지 않고, 손쉬운 사용·화면 기록·카메라·마이크·위치 권한도 요청하지 않아요. 근무 중에만 '마지막으로 키·클릭·스크롤을 한 시각' 하나를 보내요. — README '보지 않는 것', `docs/privacy.md`
5. **누가 내 근무 시간을 보나요?**
   근무 시작·종료 시각과 근무 기록은 같은 팀 안에서만 보여요. 콕 찌르기 목록·AI 토큰 순위판·미니게임 순위표는 앱을 쓰는 모두가 보는 화면이라 별명·아바타·지금 근무 중인지가 보여요. 토큰과 미니게임은 설정에서 비공개로 바꿀 수 있어요. — `docs/privacy.md` §누가 무엇을 볼 수 있나
6. **데이터는 어디에 저장되나요?**
   근무 기록·팀·프로필 같은 팀 데이터는 서버(Supabase)에, 로그인 토큰은 macOS 로그인 키체인에, 캐릭터 위치 같은 화면 설정은 이 맥에만 있어요. 메시지는 24시간, 콕 기록은 7일이 지나면 서버에서 지워져요. — README §구조 마지막 문단
7. **자동 근무 시작을 끄고 싶어요.**
   설정 → 일반 → '자동 근무 시작' 스위치를 끄면 돼요. 잘못 시작됐을 땐 그냥 근무 종료를 누르면 돼요. — `CheckSettingsView.swift:1352`, CHANGELOG 0.3.22, `docs/privacy.md` §자동 근무 시작
8. **근무 종료를 깜빡하고 퇴근했어요.**
   괜찮아요. 맥이 잠들면 덮은 시각으로, 신호가 끊기면 마지막 신호 시각으로, 오래 아무것도 만지지 않으면 마지막으로 만진 시각으로 근무가 정리돼요. 자리를 비운 시간은 근무로 세지 않아요. — README §근무 기록 '자동 마감', `docs/team-install.md` §6
9. **계정을 지우려면요?**
   아이폰 앱에서 나 → 설정 → 계정 삭제로 바로 지울 수 있어요. 맥만 쓴다면 설정 → 제보로 요청해 주세요. 근무 기록·메시지·할 일·캐릭터·루비·순위 기록이 함께 사라지고 되돌릴 수 없어요. — `docs/index.md` §계정 삭제, `docs/privacy.md` §계정 삭제
10. **AI 리밋을 보려면 로그인 정보가 밖으로 나가나요?**
    아니요. 이 맥에 이미 있는 각 도구의 로그인 정보로 그 도구의 서버에 사용률만 물어봐요. 로그인 정보는 이 맥을 벗어나지 않고, 아잉체크 서버에는 퍼센트와 초기화 시각 같은 숫자만 올라가며 나만 봐요. 끈 도구는 로그인 정보도 읽지 않아요. — `docs/privacy.md` §AI 사용량 리밋을 읽는 방법, CHANGELOG 0.3.47

예비(사용자 결정 뒤 게재): **가입할 때 소속 센터를 고르라고 나와요.** "지금 함께 쓰는 사람들이 두 센터로 나뉘어 있어서 아바타 모서리에 작게 표시하는 칸이에요. 표시만 하고 순위나 팀을 나누지는 않아요." — README '소속 센터 표시', `docs/team-install.md` §2 4. 게재 여부는 §13 위험 2에 따른다.

## 13. 소재 공백 · 위험(요약은 반환값 risks)

1. **DMG 링크가 지금 404다**(2026-10-12 06:45 KST 전후 확인. 최신 릴리스 v0.3.47 에는 zip 만 있다). 데브서버 단계에서는 버튼이 깨진 링크가 되니, 업로드가 확인될 때까지 zip 대체 경로를 함께 둔다. DMG 자체의 서명·공증·스테이플이 확인되기 전에는 "경고 없이 열려요"를 DMG 문장에 쓰지 않는다(메모리: 공증 스크립트가 실패를 삼킨다. 산출물 검증은 빌드 시각까지 볼 것).
2. **공개 랜딩과 소마판 전제가 충돌한다**: 가입 폼에 서울/부산 센터가 필수이고, 콕·메시지·토큰·미니게임 순위가 앱 사용자 전체 한 판이다. 외부 사람이 랜딩에서 받아 가입하면 그 공동체에 섞인다. 공개판(아잉콕)을 따로 만든다는 결정도 있다(메모리 aingkock-public-fork-decisions). 누구에게 열지(일반 공개, 또는 소개받은 사람 대상)와 센터 FAQ 게재 여부를 사용자가 정해야 한다.
3. README 가 코드보다 늦은 곳이 여럿이다(§12). 랜딩 문장은 이 브리프의 정본 판정을 따른다.
4. **최신 기능에는 소재가 없다**: AI 리밋(맥·폰·위젯), 체스, 테트리스, 로봇, 업데이트 배너. 맥 UI 는 0.3.38, 폰은 1.0.1(build 9) 기준 캡처다. 캐릭터와 UI 는 생성할 수 없으니, 새로 캡처(APFS 사본에서 PromoV4UIProbe, 별도 작업)하거나 글로만 다뤄야 한다.
5. "오픈소스"라고 쓸 수 없다(LICENSE 없음). "코드가 공개돼 있어요"로 쓴다.
6. 오목 스크린샷과 CHANGELOG 문장의 '판돈/걸고' 표현은 모의 도박 이슈와 닿는다. 랜딩에서는 쓰지 않고 크롭한다.
7. 제공자 로고는 공개 웹에서 상표 위험이 있다. 이름만 글자로 쓰기를 권장한다(앱 안 지시적 사용은 사용자 결정이고, 랜딩은 별개 판단).
