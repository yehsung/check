사용자 요구 셋을 어디서 어떻게 만족하나:
1. **체험 제거** — 페이지에 누르면 바뀌는 렌더가 0개다. 움직이는 것은 전부 시간(히어로 루프)·스크롤 위치(스크럽)·한 번의 문턱(행 리빌)이 일으킨다. 허용 인터랙션은 내비·다운로드·App Store·brew 복사·FAQ `<details>`·푸터 링크·트립틱 키보드 포커스뿐(§3 각 절 "금지"에 명시).
2. **다크 + 보라 조화** — 바탕은 보랏빛 밤, 보라는 지평선 림·무대 백라이트·행성 림 세 개의 빛과 선·점으로만 들어온다. 시안 실측 보라 면적: 히어로 **7.4%** · 트립틱 **3.2%** · 아웃트로 **5.4%** · 행 0.5% · 숫자 격자 0.14%. "다크하게만"으로 떨어지지 않게 화면별 하한을 수용 테스트로 건다(§1.3).
3. **레퍼런스 안무** — 가운데 정렬 큰 헤드라인 + 알약 둘 + 빛의 돔(→ 얇은 지평선 호) · 펄스 → 빛줄기 → 알림 카드(→ 앱 말풍선 렌더) 4.2초 루프 · 3장 트립틱 `[ 01 / 03 ]` + 고정 오브젝트 교체(퇴장 267ms + 등장 333ms, 꺼진 채 들어와 켜짐) · 왼쪽 레일 + 노드 + 행마다 선 → 타일 팝 → 카드 → 점 격자 → 선 탁해짐(1.3초) · 헤어라인 칸의 숫자 격자 · 검정 위 브랜드 하나(아잉)로 닫기.

## 1. 컨셉과 원칙

### 1.1 한 문단
아잉체크의 사실은 대부분 숫자로 화면에 찍혀 있다. 메뉴바의 00:00, 팝오버의 "5명 근무중", 메시지 옆의 1, "최근 12주 근무". 이 페이지는 그 숫자를 잡지의 큰 숫자처럼 가볍고 크게 세우고(Pretendard 300, 168px), 그 옆에 무거운 한 줄 헤드라인(800)을 붙인다. 숫자에서 나온 보라 지시선은 화면 가운데 격자선에서 꺾여 실제 크기의 렌더로 들어가, 그 숫자가 앱 화면의 어느 줄에 있는지 가리킨다. 렌더는 키우지 않는다 — 맥에서 보이는 그 크기 그대로, 필요한 조각만 크롭한다. 첫 화면은 얇은 보라 지평선 위의 헤드라인이고, 지평선 안쪽에는 실제 메뉴바 라벨 "03:45" 하나가 도시 불빛처럼 있다. 빛줄기가 지평선을 건너 그 라벨에 닿을 때마다 팀원의 말풍선(콕·메시지·루비)이 하나씩 떠오른다. 페이지의 끝에서는 지평선이 작은 행성이 되고, 그 위에 아잉이 서 있다.

### 1.2 레퍼런스에서 가져온 것 / 갈라진 것

| 레퍼런스(Sellix, `reference-analysis.md`) | C 에서 | 갈라진 이유 |
|---|---|---|
| 지름 94% vw 의 둥근 돔, 헤드라인이 돔 안 | **지름 222vw 의 얇은 지평선 호**, 헤드라인은 하늘(호 위), 꼭대기 = 68% vh | C 의 주인공은 글자다. 하늘을 비워 H1 이 혼자 서게 하고, 돔은 림(빛)만 남긴다 |
| 림 단면: 핵 → 9px 밝은 띠 → 안쪽 45px 감쇠, 바깥 헤일로 ≈ 0 | **그대로**(§2.2 레시피, 단면 수치 승계). 바깥은 1px 어두운 선 + 거의 없는 헤일로 | 레퍼런스의 가장 좋은 점이 "빛이 안쪽으로 감쇠"다 |

| 점 세계지도, 별, 3D 동전·카드·지구 | 없음 | 제품과 무관(brief §3) |
| 트립틱: 숫자·단락은 세로로 스크롤, 가운데 오브젝트만 고정·교체 | 숫자 띠는 **가로**로 흐르고(brief §5.1), 렌더 무대만 고정·교체 | 리드 확정 사항(가로 스크럽)을 지키되, 레퍼런스의 "오브젝트 고정 + 교체 + 점등"은 그대로 산다 |
| 트립틱 숫자 ≈ H1 × 0.97, Regular | **H1 × 1.83, Light 300** | C 의 강조. 숫자가 장면이다 |
| 세로 헤어라인 10 / 50 / 90% vw, 왼쪽 선 = 스파인 | **그대로**. 50% 선은 지시선이 꺾이는 자리이자 타일이 앉는 자리 | 격자가 정보(칼럼·꺾임점)를 가진다 |
| 행: 연결선 → 타일 팝 → 카드 → 내용 → 점 격자 → 선 탁해짐(36~39f) | **그대로**(1.3초). 연결선 = 지시선, 타일 = 50% 선 위 32px | 안무 승계 |
| 지갑 행 카운트업(0.8초) | 잔디 한 칸씩 차오름(0.8초, 렌더 픽셀만) | 숫자를 HTML 로 지어내지 않는다 |
| 목업 속 커서 데모 | 없음 → 메시지 렌더의 "1"이 한 번 사라지는 교체(1회) | 커서 합성 금지 |
| "In Numbers" 4×2, 정적 | **그대로** 4×2, 제품 사실 8개만, 카운트업 없음 | 사용자 수 금지 |
| 흰 알약 CTA | 라벤더 채움 `#C9B8FF` 1개 + App Store 공식 배지 | 가족색 |
| 엔드카드(검정 + S 마크 루프) | 아웃트로 = `#0A0910` 위 작은 행성 + 아잉 idle 루프 + 헤드라인 1줄 + 버튼 1개 | 페이지라서 버튼 하나는 둔다 |

### 1.3 절제 원칙(구현자가 매번 확인 — 8줄)
1. **글로우는 화면당 1개.** 글로우 = blur ≥ 16px 이거나 보라 알파 ≥ .2 인 라디얼. 페이지에 3개(`hero-horizon`·`figures-stage`·`outro-planet`)뿐이고, 각각 자기 절이 뷰포트의 70% 이상일 때만 켜진다(§2.2 GlowGate).
2. **보라 면적 예산**(측정: 뷰포트 캡처의 HSV H 245–295° · S ≥ .35 · V ≥ .30 픽셀 비율, 스크립트는 §5.4): 히어로 6–10% · 트립틱 2.5–5% · 아웃트로 3–7% · 행 0.3–1.5% · 그 밖의 뷰포트 0.02–1.5%. **어느 뷰포트도 0.02% 미만(보라가 하나도 안 보임) 금지, 12% 초과(보라 범람) 금지.** 조용한 절에도 보라 요소가 하나씩 있다: 절 제목 = 레일 머리 점 + 첫 구간, 숫자·설치 = 윗변 이음매 선, FAQ = 열린 행 왼쪽 2px 막대 + ▸.
3. **평평한 보라 면은 32px 타일 6개뿐**(행마다 1개). 카드·띠·버튼·섹션 바탕에 보라를 칠하지 않는다(주 버튼은 라벤더 `#C9B8FF`, 채도 .28 이라 보라 예산에 들지 않는다).
4. **렌더는 1× 이하.** 1 CSS px = 1pt(맥 실제 크기). 줄이는 건 되고 키우는 건 안 된다. 예외는 메뉴바 라벨 하나(2×, 22pt 는 첫 화면에서 안 읽힌다). 렌더 위에는 아무것도 그리지 않는다 — 지시선은 **렌더 테두리에서 멈춘다**.
5. **큰 숫자는 렌더에 있는 숫자만.** 각 숫자는 지시선이 가리키는 렌더 좌표를 `data/figures.ts` 에 갖는다(§3 앵커 표). 앵커가 없는 숫자는 숫자 격자(출처 줄 번호 필수)로만.
6. **한 화면에 큰 것 하나.** 숫자 하나 + 렌더 하나 + 지시선 하나. 말풍선은 화면에 1개까지.
7. **불투명도는 선형, 이동·크기는 ease-out(들어올 때)/ease-in(나갈 때).** 캐릭터 영상에 CSS 변형·필터 금지. 렌더에 grayscale·blur 필터 금지(점등은 렌더 뒤 빛과 테두리로만).
8. **카드 호버·섹션 페이드업·스크롤 힌트·키커 남발 없음.** 눈썹 칩은 히어로 1개, 카테고리 라벨은 한글 14px.

### 7.2 사용자가 싫어할 위험 셋과 대안
1. **"또 다크하게만"** — 행·숫자·FAQ 구간은 보라가 0.1–0.5% 다(레퍼런스 행 구간도 ≈ 0.55%). 스크롤 대부분이 이 구간이라 인상이 어둡게 남을 수 있다.
   대안: (a) 행 렌더 뒤에 트립틱 백라이트의 1/3 세기 고리(알파 .2, 화면당 1개)를 더해 행 화면 1.5–2.5% 로 올린다. (b) 레일 점등 구간을 1px → 2px + `--violet` 100%. (c) 숫자 격자 칸 왼쪽 헤어라인 전체를 `--violet-deep` 으로. 셋 다 토큰 한 줄씩이라 통합 단계에서 실측(§5.4)을 보고 켤 수 있다.
2. **"렌더가 너무 작다"** — 1× 원칙 때문에 팝오버 조각이 322px 폭이다. 1440 화면에서 "작게 정확하게"가 "안 보인다"로 읽힐 위험.
   대안: 렌더 칼럼이 600px 이상일 때만 1.15× 까지 허용(@2x 원본이라 레티나에서 1.15× 는 1.74 px/px — 무르지 않는 한계). 더 키워야 하면 크롭을 @3x 원본에서 pt × 2.5 로 다시 굽는다(바이트 +55%).
3. **Light 숫자가 한글에서 가늘고 차갑다** — "5명"·"12주"·"콕."의 한글 획이 300 에서 얇게 보일 수 있다(라틴 숫자보다 획이 많다).
   대안: 숫자 서브셋을 `wght=400` 또는 `500` 으로 다시 인스턴스(바이트 2.6–2.8KB 로 같다). 토큰 `--figure-wght` 하나와 스크립트 인자 하나만 바뀐다. 또는 숫자는 300, 한글 단위(명·주)만 600 시스템 글자로(숫자 격자의 단위 방식).
