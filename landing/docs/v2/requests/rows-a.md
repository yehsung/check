## 1. (P1 · 통합 + 리드) 행 보라 하한 V3·V4(≥ 1.0%)가 지금 값으로 빨강 — DECISIONS D13 손잡이만으로는 닿지 않는다

**무엇**: SPEC §2.9 의 HSV 알고리즘(H 245–295° · S ≥ .35 · V ≥ .30, 1440×900, 캔버스 중심 = 화면 50%, 1s 이상 대기)으로 잰 값:

| 위치 | 지금(α .34) | 하한 |
|---|---|---|
| V3 R1 가운데 | **0.475%** | 1.0% |
| V4 R3 가운데 | **0.291%** | 1.0% |
| (참고) R2 가운데 | 0.209% | 표에 없음 |

**왜 모자란가(내역, R1 α .34)**: 바닥 빛 0.176% · 타일 0.155% · 노드 0.039% · 스파인 토막 0.026% · 선·점 격자 0.057%.
- 바닥 빛 타원은 중심 α .34 → 55% 지점 α .12 라서 V ≥ .30 을 넘는 핵이 반지름의 ≈ 23% 뿐이다(α ≥ .246 이어야 bg-0 위에서 V ≥ .30).
- **R2·R3 은 바닥 빛 기여가 0.000%** — 페이드 없는 주 렌더(`character-panel`·`minigame`)의 `--shadow-window`(`0 28px 56px -18px rgba(0,0,0,.72)`)가 렌더 아래 타원 핵을 덮는다(R1 은 아래 40 페이드라 바깥 그림자가 없어 보인다). 바닥 빛 상자가 주 렌더보다 먼저 그려지는 것(RowCanvas 순서)은 맞다 — 위로 올리면 렌더 덧그리기가 된다.

**D13 손잡이와 그 밖의 조합(이 페이지에만 주입해 잰 값)**:

| `.floor-light` 중심 α / 55% α | 위치 | R1 | R3 |
|---|---|---|---|
| .34 / .12(지금) | SPEC top | 0.475% | 0.291% |
| .40 / .12 | SPEC top | 0.583% | 0.320% |

| .55 / .20 | top + 40 | 0.998% | 1.162% |

**제안(결정 필요 — 나는 아무것도 적용하지 않았다)**:
- (a) 리드: 행 하한을 실측에 맞춰 0.4%(R3 D13 끝값) 안팎으로 내린다. 1440 캡처(`shots/1440-f-message.png`·`1440-f-break.png`)에서 바닥 빛 웅덩이·타일·노드·보라 토막이 이미 '보라'로 읽힌다 — "너무 다크" 판정의 근거는 V0·V1·V9 가 진다.
- (b) 하한을 지키려면 globals 두 값 + 행 데이터 위치를 함께 바꿔야 한다(D13 은 α 하나만 허락):
```diff
-  .floor-light { … background:radial-gradient(ellipse closest-side, rgba(126,94,250,.34), rgba(126,94,250,.12) 55%, transparent); }
+  .floor-light { … background:radial-gradient(ellipse closest-side, rgba(126,94,250,.55), rgba(126,94,250,.20) 55%, transparent); }
```
  그리고 `rows-a.data.ts`·`rows-b.data.ts` 의 `floor.top` 을 각 +40(주 렌더 아랫변과 같게: R1 408 · R2 410 · R3 480) — SPEC 의 '통합 ±8px' 밖이라 승인 후 rows-a/통합이 한 줄씩 고친다. 이래도 R1 은 0.998% 로 경계다.
- 다른 곳에 보라를 더하는 길(타일·선 굵기 등)은 D13 이 막고 있어 쓰지 않았다.

## 2. (P2 · 통합 · 리드 선택) R1 아래 40px 페이드가 '안 읽음 1' 줄을 살짝 흐린다

- **무엇**: `ui/message-unread-panel` 크롭의 마지막 줄(14:04 "1 좋아요! 배포하고 1층에서요")이 표시 상자 아래 ≈ 30px 에 있어 SPEC §S4 R1 의 `fade.bottom = 40` 마스크 안에 든다. "1" 은 보이지만(마스크 α ≈ .75) R1 의 '숫자 움직임'이 흐린 띠 속에서 일어난다. 증거: `shots/r1-tail-unread-2x.png` ↔ `r1-tail-read-2x.png`.

## 3. 알림 — SPEC 과 글자가 다른 곳(이유 있음)

- **기능 절 제목 높이 385px**(SPEC 표 360): 위 96 · 칩 30 · 칩→H2 20 · H2 139(60 × 1.16 × 2) · H2→서브 20(SPEC §2.5) · 서브 32 · 아래 48. 1440×900 문서 높이에 +25px(여유 284 안). 넘치면 칩→H2 를 12 로 줄이면 −8.
- **desk 에서만 10% 세로 격자선(`Gridlines lines="left"`)을 기능 절 제목에도** 깔았다 — 트립틱의 10% 선이 스파인 머리 점까지 끊기지 않게(SPEC §2.5 "왼쪽 선이 기능 절에서 스파인이 된다", §S3 와이어 `│10%`). tab 은 넣지 않았다: tab 의 스파인은 x 32(SPEC §4 · `Rail`)인데 `.gridlines--left` 는 10%(768 에서 76.8)라 이어지지 않는다 — **tab 에서 트립틱 10% 선(76.8)과 행 스파인(32)이 어긋나는 것은 SPEC §4 표 자체의 불일치**(통합·리드 참고, 내 파일로는 못 고친다).
- 행 데이터의 `ALT` 는 `fixtures.ts` 표를 그대로 읽는다(빈 값 0 을 스크래치 테스트가 단언).
