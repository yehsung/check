# 랜딩 v3 — 다크 리퀴드 글래스 (정본, 2026-10-22)

이 문서가 v3 의 **최상위 정본**이다. v2 문서(docs/v2/*)는 사실(문구 출처·렌더 이름·alt·릴리스 API)을 찾을 때만 본다.

여전히 유효한 이전 피드백(어기면 다시 거부된다):
- 웹에서 앱을 **체험하는 기능 금지**(가짜 앱 조작·클릭하면 앱처럼 반응하는 데모). 보여 주기만 한다.
- 글은 적게. 핵심 기능 6개만: 근무 타이머 · AI 토큰 사용량/리밋 · 메신저 · 근무 리듬/잔디 · 미니게임 · 아이폰-맥 연동.
- 어두운 면적이 넓게 비면 안 된다. **보라 빛이 넓게 퍼져** 있어야 한다(다크 + 보라의 조화).
- 앱 화면 렌더는 **통째로**. 잘린 조각(예: 토큰 순위판을 165×423 으로 썬 슬라이스) 금지. 크롭·마스크로 자르지 않는다.

## 1. 지금 판이 실패한 이유(우리가 본 것)
1. 장면 사이에 빈 검정이 너무 넓고, 렌더가 화면에 비해 작다. 글자도 작고 흐리다(본문 14px 회색).
2. 스파인 세로선·격자선·와이어가 템플릿 장식처럼 보인다. 재질이 없다(전부 평평한 검정 위 그림).
3. 히어로의 큰 원(돔)이 흔하다.
4. 설치 절이 비좁고 brew 는 한 줄짜리 회색 상자라 거의 안 보인다.

## 2. 방향 — "빛 위의 유리"
macOS 26 의 리퀴드 글래스를 웹으로 옮긴다. 이 앱은 **메뉴바 앱**이고 macOS 26 의 메뉴바·팝오버가 바로 리퀴드 글래스다 —
그래서 이 사이트에서 유리는 장식이 아니라 제품이 사는 재질이다.
- 바탕은 깊은 보랏빛 밤. 그 위에 천천히 흐르는 **보라 오로라 빛**이 화면 전체에 넓게 깔린다(유리가 굴절시킬 재료).
- 그 위에 **유리 판**들이 뜬다: 메뉴바 내비 · 앱 창 베젤 · 기능 전환 세그먼트 · 터미널 · 버튼 · FAQ 판.
- 유리는 뒤의 빛과 글자를 **굴절**시키고(가장자리 렌즈), 위 테두리에 **스페큘러 하이라이트**가 있고, 마우스를 따라 빛이 움직인다.
- 대담함은 한 곳에: **히어로의 유리 팝오버**(메뉴바 상태 항목에서 떨어지는 앱 창). 나머지는 조용하고 절제한다.

| focus | #B9A8FF | 포커스 링 |

유리 재질(세 단계 — 클래스 또는 컴포넌트 prop 으로):
| 단계 | 쓰는 곳 | blur | 채움(흰색 α) | 모서리 |
|---|---|---|---|---|
| thin | 메뉴바 내비, 칩, 명령 알약 | 18px | .05 → .02 | 메뉴바 0 / 알약 999 |
| regular | 터미널, FAQ 판, 세그먼트, 설치 카드 | 28px | .07 → .025 | 22px |
| thick | 히어로 팝오버 베젤, 기능 무대 베젤 | 36px | .09 → .03 | 30px |
공통: `saturate(170–190%)`, 위 1px 안쪽 하이라이트(흰 .25), 테두리 그라디언트(왼위 흰 .55 → 오른아래 .04, 끝에 라일락 .25 — mask-composite 로 1px 링),
깊은 그림자(아래로 번진 보라빛 검정), 포인터를 따르는 스페큘러(::after 방사 그라디언트, `--mx/--my`, pointer:fine 에서만, rAF 스로틀).
굴절(가장자리 렌즈): 데스크톱 Chromium 에서만 SVG `feDisplacementMap`(요소 크기에 맞춘 가장자리 변위 맵 + RGB 채널별 다른 scale 로 미세 색수차)을
`backdrop-filter: url(#…) blur() saturate()` 로 건다. **동시에 화면에 보이는 굴절 요소 ≤ 3개**(내비 · 히어로 팝오버 베젤 · 세그먼트 물방울).
Safari·Firefox·모바일은 blur 폴백(같은 채움·테두리·하이라이트) — 폴백도 그 자체로 예뻐야 한다. `-webkit-backdrop-filter` 를 꼭 같이 쓴다.

글꼴: Pretendard 유지(이미 서브셋됨 — SF 와 짝이 맞는 한글). 제목 600, 자간 -0.035em. 크기: H1 clamp(44px, 6vw, 84px)/1.04 · H2 clamp(34px, 4.2vw, 56px)/1.08 ·
H3 26–30px · 본문 17–18px/1.6(ink-2) · 작은 글 14px. 숫자(타이머)는 tabular. 터미널은 JetBrains Mono.
**새 한글 문구를 넣으면 `npm run subset` 으로 글꼴 서브셋을 다시 만들어야 한다**(prebuild 의 check-glyphs 가 빠진 글리프를 잡는다).
금지: 한 단어만 색/기울임 강조, 모두 대문자 라벨, 제목 위 눈썹 라벨 남발, 버튼 글자 끝의 '→', 01/02 번호(순서가 아닌 것에).

## 4. 배치
### 4.1 바탕 — 오로라 장(場)
- `position:fixed` 전체 화면 층(z -1): 큰 빛 덩어리 4–5개(violet 가장 크게, orchid, indigo 아래쪽, rose 작게).
  CSS `filter: blur` 를 큰 요소에 걸지 말고 **부드러운 방사 그라디언트**로 만든다. transform 으로 40–70초 주기 아주 느린 표류. 탭이 숨으면·감속 모션이면 멈춤.
- 절마다 유리 판 뒤에 **국소 빛**(absolute 방사 그라디언트)을 1–2개 둔다 → 어느 스크롤 위치에서도 유리 뒤에 색이 있다.
- 미세 노이즈 결(3% 이하, 타일 데이터 URI)로 그라디언트 띠 방지.
- 기준: 1440 의 어느 화면 높이 구간도 "보라 빛이 안 보이는 순검정 화면"이 없다.

### 4.2 내비 = 유리 메뉴바
화면 맨 위 전폭 **유리 메뉴바**(thin, 높이 44–48px, 굴절). macOS 메뉴바처럼:
- 왼쪽: 앱 아이콘 + "아잉체크"(굵게) · 기능 · 설치 · 자주 묻는 것 (메뉴 항목처럼 13–14px).
- 오른쪽: [Mac용 다운로드](작은 유리 버튼) · **상태 항목**(앱 아이콘 + "03:45" tabular — 근무 중 상태, 실제 앱 메뉴바 라벨을 글자로 재현).
- 스크롤해도 붙어 있다. 아래로 스크롤 중엔 그대로(숨기지 않음).
- 390: 아이콘+이름 · [다운로드] 만(링크 숨김). 애플 로고()는 쓰지 않는다.

### 4.4 핵심 기능 6개 — 고정 무대 + 유리 세그먼트
데스크톱(≥1024 폭 그리고 ≥760 높이, 감속 모션 아님):
```
          [ 근무 타이머 | AI 토큰 | 메신저 | 근무 리듬 | 미니게임 | 아이폰 ]   ← regular 유리 세그먼트, 활성 칸 = 굴절 물방울
  ┌ 왼쪽 38% ─────────────┐   ┌ 오른쪽 62% thick 유리 무대 ───────────────┐
  │ 제목 2줄(H2 크기)      │   │   장면의 렌더 구성(통째, 겹치지 않게)       │
  │ 문장 1개               │   │   장면이 바뀌면 크로스페이드 + 살짝 굴절 출렁 │
  └────────────────────────┘   └──────────────────────────────────────────┘
```
- 절 전체 높이 = 6 × 약 85vh. 무대(세그먼트+두 열)는 `position: sticky` 로 고정, 스크롤 진행으로 활성 장면이 바뀐다.
- 세그먼트 칸을 누르면 그 장면 스크롤 위치로 부드럽게 이동(체험 아님 — 목차). 물방울은 칸 사이를 움직일 때 가로로 늘었다 줄어든다(액체).
- 키보드: 세그먼트는 tablist 가 아니라 **목차 링크 목록**(각 장면 id 로 #링크) — 포커스 링 보이게. 활성 칸 aria-current.
- 장면별 렌더 구성은 v2.1 장면(components/features/scenes.data.ts)의 렌더 짝을 그대로 쓰되 와이어·노드는 버린다. 렌더 표시 배율: 팝오버류 ≤ .5,
  센터 배지 든 패널(token-month · league · minigame)은 ≤ .5. 무대 안에서 렌더가 잘리면 안 된다(무대 높이 ≤ 100svh - 내비 - 세그먼트 - 여백).
- 데스크톱 외(태블릿·폰·감속 모션·낮은 창): 고정 없음. 장면을 세로로 쌓는다 — 제목 · 문장 · 유리 베젤 안 렌더(폭 맞춤, 통째). 세그먼트는 숨긴다.
- 장면 문구는 v2.1 그대로를 기본으로 하되 더 줄일 수 있으면 줄인다(제목 2줄 + 문장 1개, 장면 6 의 사실 문장 "근무 시작·종료는 맥에서 해요." 유지).

### 4.5 설치 — brew 를 주인공으로
```
            복잡한 과정 없이 / 명령어 한 줄로 설치해요              (H2, 가운데)
  ┌ regular 유리 터미널 (넓게, ~60%) ──────────────┐   ┌ regular 유리 카드 ────────┐
  │ ● ● ●                 zsh                      │   │ Homebrew를 안 쓴다면       │
  │ $ brew install yehsung/check/aing-check  [복사] │   │ [aing-check.dmg 다운로드]  │
  │ ==> Tapping yehsung/check                       │   │ v{ver} · {mb}MB · 공증     │
  │ ==> Downloading aing-check {ver}                │   │ 열기 → Applications 로 끌기│
  │ ==> Installing Cask aing-check                  │   ├──────────────────────────┤
  │ ==> Moving App 'aing-check.app' to '/Applications/aing-check.app'│ iPhone  [App Store] [QR] │
  │ 🍺  aing-check was successfully installed!       │   │ iOS 18 이상 · 무료        │
  └─────────────────────────────────────────────────┘   └──────────────────────────┘
   업데이트도 한 줄 — `brew upgrade --cask aing-check` [복사]   ·   앱 안 [지금 업데이트] 도 brew 로 알아서 처리돼요.
```
- 터미널: macOS 창 모양(신호등 점 3개, 제목 "zsh"), 유리(regular) 위에 아주 옅은 어두운 틴트로 글자 대비 확보. 모노 15–16px.
- 처음 화면에 들어올 때 **한 번** 명령이 타이핑되고(약 1.2초) 출력 줄이 차례로 뜬다(줄당 120–250ms). 감속 모션/JS 없음 = 처음부터 완성 상태.
  버전은 릴리스 API 값(하드코딩 금지). 출력 줄은 실제 brew 형식과 맞게(Tapping · Downloading · Installing Cask · Moving App · 🍺 성공).
- [복사] 는 진짜 복사(클립보드) + "복사했어요" 상태 + 라이브 영역 알림. 체험이 아니다(사이트 기능).
- 명령 문자열의 정본은 `data/fixtures.ts` 의 `BREW`(install · upgrade). README 의 업그레이드 문구와 같아야 한다.
- 오른쪽 카드: DMG(`/api/download`) 버튼·메타 한 줄·두 걸음 / iPhone(App Store 배지·QR(데스크톱)·"iOS 18 이상 · 무료").
- 390: 터미널(가로 스크롤 없이 줄바꿈 — 명령은 '/' 뒤 줄바꿈 허용) → DMG 카드 → iPhone 카드. iOS 기기면 iPhone 카드 먼저(기존 data-platform 규칙).

| f-iphone | 폰(지금 탭) + 내 오늘 스몰 위젯 | 폰(지금 탭) + **AI 리밋 미디움 위젯** + 내 오늘 스몰 위젯(폰 < 768 에선 스몰 위젯 생략 가능 — 폰 화면이 같은 3:45:00 을 보여 준다) |
규칙은 그대로: 렌더 통째(크롭·마스크 0) · 겹침 0 · 배율 상한 · 고정 무대 안에서 잘림 0. 새 렌더는 `scratchpad/agents/render-mac/out`·`render-ios/out` 에서 온다.

### 9.2 내비
- 오른쪽 상태 항목(아잉 아이콘 + 03:45)을 **지운다**. 오른쪽엔 [다운로드] 하나.
- 왼쪽 로고(아이콘+아잉체크) 클릭 = 페이지 맨 위(히어로)로. 홈에서 `/` 링크는 같은 URL 이라 아무 일도 안 일어날 수 있으니 직접 처리: 맨 위로 스크롤(감속 모션이면 즉시), 주소의 `#…` 를 지우고, 포커스를 문서 맨 앞으로. 다른 경로(/licenses 등)에선 `/` 로 이동.
- 폰(< 768)에선 [다운로드] 가 DMG 를 받지 않는다(폰에 DMG 는 쓸모없다) → `#install` 로 이동.

### 9.3 설치
- 업데이트 줄 삭제(§8). 부제 교체(§8). DMG 카드 문구 그대로.

### 9.4 폰·태블릿 (< 1024, 특히 390) — 데스크톱 모양 불변
1. **히어로 CTA(< 768):** App Store 배지를 첫 화면 주 행동으로 올린다. [App Store 배지] 와 [Mac용 다운로드](유리 보조 버튼)를 한 줄에, 그 아래 메타 `무료 · iOS 18 이상 · macOS 14 이상`. 히어로 brew 알약은 폰에서 숨긴다(명령이 두 줄로 꺾여 어색하고, 폰에선 쓸 수 없다 — 설치 절이 보여 준다). iOS 기기·폰 폭 모두 같은 규칙.
2. **히어로 팝오버(< 768):** 폭 꽉 찬 거대한 팝오버 + 그 아래 혼자 떠 있는 아잉이 어색하다 → 팝오버를 폭 ~300 안팎으로 줄여 가운데, 아잉은 데스크톱처럼 베젤 아래 왼쪽 모서리에 겹쳐 붙인다(혼자 떨어진 빈 줄 금지). 팝오버 위 파란 빛 공 덩어리가 튀지 않게.
3. **명령 표시(전부):** 명령 중간 줄바꿈 금지. 터미널은 폰에서 모노 글자를 줄이고 [복사] 를 제목 줄(zsh 오른쪽)로 옮겨 명령이 한 줄에 들어가게. 출력 긴 줄(Downloading URL·Moving App)은 폰에서 줄바꿈 허용하되 들여쓰기 정렬. 타이핑 전 빈 터미널이 길게 비어 보이지 않게(예약 높이는 실제 출력 높이와 같게). 아웃트로 brew 알약도 폰에서 한 줄(아이콘 복사 버튼) — 안 들어가면 폰 아웃트로에선 숨긴다.
4. **아웃트로(< 768):** 히어로와 같은 순서 — App Store 배지가 먼저.
5. **장면 묶음(< 1024):** 렌더가 세로로 너무 길게 이어지지 않게(장면당 화면 높이 ~1.5배 이내 목표). 말풍선 같은 장식은 폰에서 과하게 커지지 않게. 장면 사이 간격 정돈.
6. **글 줄바꿈:** 가운뎃점으로 이은 묶음(`오목·체스·테트리스는`, `Claude Code·Codex·Gemini의`, `팀 현황·메시지·할 일·게임은`)이 `·` 앞에서 끊기지 않게.
7. **절 간격:** 설치 카드 → FAQ 제목 사이 같은 큰 빈 공간을 폰에서 줄인다.
8. **푸터(< 768):** 링크가 한 줄에 하나씩 세로로 길게 늘어서지 않게 — 줄바꿈되는 가로 묶음.
9. 768–1023(태블릿)도 같이 점검: 어색한 빈칸·넘침 0.
